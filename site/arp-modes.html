Digitone II Mods / arp modes

Arp Modes

The Digitone II names eight arpeggiator modes and offers five. This adds two of the missing ones, SHUF and RAND, as real modes with their own code. Pick your firmware, download a signed image.

Everything happens in this tab. Your firmware file is never uploaded — this page has no server to upload it to. It is static files on GitHub Pages; you can read every line in the repository.

Prove your way back before you flash anything. The Early Start-up Menu reflashes stock firmware over MIDI. Do that once, with an unmodified image, before you flash a modified one — and back up your +Drive, which no tool here can recover.

What it adds

The ARPEGGIATOR MODE menu goes on past CYCL to the two new modes, and stops at RAND. Every address this mod writes is checked to hold its stock bytes first; an image that differs anywhere is refused rather than written somewhere plausible.

SHUF
Plays every note in the range once per cycle, in a new order each cycle. The note that ends one cycle never starts the next
RAND
Picks a random note from the range on each step; the same note can come twice
The range
The notes you hold, across RNG + 1 octaves, as in the other modes
The rest
SPD, LEN, N.LEN, the step mask and the note offsets work as in every other mode: the new code only chooses the note
Not included
CHRD, the eighth name, stays hidden
Writes
—

A sound saved in SHUF or RAND opens with the arp OFF on stock firmware, or on any build without this mod. It is stored as mode 5 or 6, and stock turns anything above CYCL into OFF when it loads a sound.

Confirmed on a Digitone II, 2026-09-26. This page applies exactly the bytes of that build, checked byte for byte when it is packaged.

Build it

The image is rebuilt, re-signed with the key derived from your own file, and every integrity field is checked again. Nothing downloads unless all of them pass.

Combining with other mods

Each page applies one mod. To combine them, build on one page, then load the downloaded file into the next. This mod combines with every other one, in either order: it writes 8 places inside section 3, changes no length and appends nothing.

  • MIDI Arpeggiator — combines. A MIDI track's arp runs the same step, so SHUF and RAND should reach MIDI tracks too; that has not been tried.
  • A Fourth LFO — combines, in either order.
  • LFO Waves, Boot Screen — combine. Their appended data moves no address this mod uses.
  • FX Modulation, Modulation Destinations — combine.
  • Transient Swapper — combines; it only writes the DSP image.
  • Arpeggiator p-locks — combines; command line only, dnfw mods apply firmware.syx --mod arpplocks --mod arpmodes. Its MODE lock then reaches SHUF and RAND too.

What "combines" means here. The bytes each mod writes are checked not to overlap, and this page's output is checked byte for byte against the command line's, alone and after the MIDI Arpeggiator or A Fourth LFO. The arp modes were tested on hardware on their own; a combined image has not been flashed.
