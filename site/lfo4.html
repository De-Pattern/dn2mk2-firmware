A Fourth LFO

The Digitone II has three LFOs per track and an empty fourth page under [MOD]. This fills it with a fourth LFO that behaves like the other three. Pick your firmware, download a signed image.

Everything happens in this tab. Your firmware file is never uploaded — this page has no server to upload it to. It is static files on GitHub Pages; you can read every line in the repository.

Prove your way back before you flash anything. The Early Start-up Menu reflashes stock firmware over MIDI. Do that once, with an unmodified image, before you flash a modified one — and back up your +Drive, which no tool here can recover.

Apply LFO4 last. It copies the instrument's parameter table into a new place with room for ten more records, and from then on the firmware reads the copy. A mod that edits that table has to be in the image before the copy is made, or its edit lands on a table nothing reads.

Combines with FX Modulation, Modulation Destinations, the MIDI Arpeggiator and Arpeggiator p-locks (command line): build those first, then load their download here. Not with LFO Waves or Boot Screen: all three need the same start-up hook and the same appended area, and this page refuses an image either of them has built.

What it adds

A fourth page under [MOD], with the controls LFO1-3 have. Every address this mod writes is checked to hold its stock bytes first; an image that differs anywhere is refused rather than written somewhere plausible.

Where
On a synth track: [MOD], the fourth page. Its DEST browser works like LFO1-3's
Plays
Modulates on every voice, so polyphonic tracks and tracks that move between voices are modulated too
Keeps
Its settings are stored with the sound by SAVE PROJECT, and survive a power-cycle even without a save, like any stock parameter
Not included
MIDI: LFO4 has no NRPN numbers, so it cannot be set or recorded over MIDI
Writes
—

Confirmed on a Digitone II. The page opens with the stock LFO controls, its DEST browser works, it modulates on every voice, and its settings are kept by an explicit SAVE PROJECT and survive a power-cycle without one. This page applies exactly the bytes of that build, checked byte for byte when it is packaged.

None of Elektron's data ships with it. The copied parameter table — the 320 stock records and LFO4's ten, which are LFO3's with five fields rewritten — is rebuilt from your file when you press Build.

3

Build it

The image is rebuilt, re-signed with the key derived from your own file, and every integrity field is checked again. Nothing downloads unless all of them pass.

Combining with other mods

Each page applies one mod. To combine them, build on the other page first, then load its download here: this one goes last. It writes 204 places in section 3 and appends 23.7 KB to it.

  • FX Modulation — combines, applied first. Its ten Chorus record masks are carried into LFO4's copy of the table. In the emulator every LFO page, LFO4's included, lists the 24 FX destinations; LFO4 actually aimed at one has not been tried. The FX page refuses an image this page has built.
  • Modulation Destinations — combines, applied first. Its thirteen opened destinations are carried into the copy. That page refuses an image this page has built.
  • MIDI Arpeggiator — combines, in either order. No shared bytes.
  • Arpeggiator p-locks — combines; command line only, dnfw mods apply firmware.syx --mod arpplocks --mod lfo4.
  • Transient Swapper — combines; it only writes the DSP image.
  • LFO Waves, Boot Screen — do not combine. They need the same start-up hook and appended area.

What "combines" means here. The bytes each mod writes are checked not to overlap, and this page's output is checked byte for byte against the command line's, alone and after FX Modulation. LFO4 was tested on hardware on its own; a combined image has not been flashed.
