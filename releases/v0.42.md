# v0.42 · LEAN

patcher: de-pattern.github.io/dn2mk2/patcher.html

the Monomachine machines re-coded for this firmware: same sound, bit for bit, a good deal lighter on the DSP. DDRW's bit reduction now rounds exactly as a real Monomachine. and the loud spikes and rimshot-like clicks when a voice moves between Machinedrum machines are gone.

**changed**
- **lighter Monomachine machines**: DDRW about 27% fewer DSP instructions, SID 25%, DENS 21%, VO-6 18%, DPRO WAVE 15%, and most of their loops' memory traffic gone. every output word is identical to before (checked over 1,098 runs: all 366 reference cases plus knob changes mid-note)
- **DDRW's bit reduction exact**: at heavy BR (around 112) it rounded one step differently from a real Monomachine. it now does what the Monomachine's DSP does (one fixed-point multiply), and all 366 Monomachine reference cases match (the three that didn't: 44 dB, now 115 dB)
- the Monomachine reference check is back in the gate in full
- **Machinedrum voices start clean**: a voice that last played another machine (a ringing PI-RS, say) carried its old state into the next note, which gave the clicks on PI-HH and the loud spikes every few voices. a voice that changes machine now starts exactly as a fresh one (checked bit for bit over every MD machine)
- the Machinedrum sample reader re-coded the same way (lighter, identical output)
- **GRID and SLICE menus let go**: the GRID random-locks screen no longer stays over other pages, and YES no longer reopens it on another track (thanks NiKo)
- **a REC trig that records nothing says why**: the track's REC view shows BUFS OFF, MANUAL REC, NO ROOM or NOT ARMED for a few seconds (thanks NiKo)

**test**
1. a busy pattern with a few SID, DDRW, VO-6 voices: hold FUNC on a Monomachine page and compare the load meter with v0.41's. tell us the numbers
2. the PI-HH / PI-BD / TRX-CP pattern that spiked: no clicks or spikes, with PERC on any voice count
3. GRID random locks: open it, go to another page or track, YES: it stays closed
4. a REC trig on a track with buffers off: the REC view says why
5. DDRW with BR1 or BR2 near the top: the steps sound as before (and as a Monomachine)
6. everything from v0.41 still (rec trigs, QPLAY/QREC, slides)

**known issues**
- one recorder: a REC trig while the other buffer records cuts that take
- buffers are off in a project with saved samples in SAMP 124-127 (from v0.32 or older)
- an LFO on SAMP or SLCE doesn't step through the loaded samples yet
- preset pool trig locks don't work with the mod's machines yet
