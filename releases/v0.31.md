# 🚨 v0.31 is out: DRIVE

patcher: de-pattern.github.io/dn2mk2/patcher.html

**fixed / new**
- **the +Drive library**: about 20 GB on the +Drive for your samples, in folders, up to 2,048 of them. FUNC+YES in the sample list now opens on **PROJECT RAM** (your slots, as before) or **+DRIVE** (the library)
- in +DRIVE: YES ticks samples, RIGHT gives **LOAD TO PROJECT** (into free slots, takes seconds) and **LOAD TO TRK** (loads it and puts the track on it), DELETE, SELECT ALL. a sample already in the project isn't loaded twice
- sending into the library: the import tool has a new mode, **Into the +Drive library**, which also lists what's on the +Drive and can delete. nothing in your project changes until you load it
- **faster start**: at power-on the samples your kit actually uses load first, so the pattern can play while the rest load. the waveform shows **LOADING n%**
- leaving the browser: NO goes up a level, NO held jumps to the top, any page key closes it
- **PERC dropouts with dynamic voice allocation** (thanks depaffect): finished Machinedrum voices kept eating DSP time, so with lots of PERC tracks the sound could cut out. now a voice that has died away stops costing anything until its next note

**test**
1. power on with samples kept: LOADING n% on a sample track, and the pattern plays while it counts
2. import tool → Into the +Drive library → send a few WAVs into a folder. on the unit: FUNC+YES, +DRIVE, your folder
3. RIGHT on one → LOAD TO PROJECT: it gets a slot and plays. LOAD TO TRK on another: the track switches to it
4. 8 PERC tracks, dynamic allocation, busy pattern: does it still cut out? (watch for CPU on the PERC page)
5. NO / NO held / page keys behave as above

**known issues**
- not in the library yet: rename, preview, move, create folder, slices
- one sample pool for all projects for now (per-project pools come after v0.32)
- FUNC + turn on the custom machines' controls: fixed in v0.32
- heavy DSP use can still run out of time: v0.32 is the big fix for that
