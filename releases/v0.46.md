# v0.46 · KEEPER

patcher: de-pattern.github.io/dn2mk2/patcher.html

your recordings now land in +DRIVE > RECORDED, like the DT2, and the naming screen takes long names

**recordings saved to +DRIVE > RECORDED**
- every recording you save (RECORD NOW, or a BOUNCE take with FUNC + YES) is saved to the project as before, then copied into +DRIVE > RECORDED under the name you gave it. it outlives the project: load it into any other project from the +DRIVE browser
- the copy runs in the background, only while nothing else is loading or saving. the slot then shows as that +Drive sample in the browser
- the recording is in the project first, so nothing can lose it. a power cut during the copy leaves either no entry or the whole one, never a broken sample
- +Drive full: the recording stays in the project only, and the recorder's line says +DRV FULL
- recordings made before v0.46 stay where they are, untouched

**longer names**
- FILE NAME takes up to 35 characters for a recording (as the +Drive library keeps them), and scrolls with << and >> as the DT2's does
- RENAME in PROJECT RAM takes long names too, where the project keeps them; a new folder's name up to 30
- the short name SAMP shows is the first 7 letters
- new recordings are still named REC + the slot number (REC041), as SAMP shows them. the DT2's REC0000 counter would need a change to how projects are stored, so it waits

**fixed**
- BOUNCE's BUF showed 0%..100% in the header: it now reads 1..8 (thanks depaffect)

**safety**
- every emulator check in the gate now fails if our code reads from an address where nothing lives (the kind of read behind v0.44's freeze)
- the recordings' copy is tested with a power cut after every step, a full +Drive, the slot changed mid-copy, and a computer send arriving during a copy

**test**
1. record something (FUNC + VOICE, RECORD NOW), TRIM, give it a long name, YES: it plays from its slot; open the +DRIVE browser > RECORDED: it's there under the whole name, shown as loaded
2. new project: load it from +DRIVE > RECORDED: it plays
3. a BOUNCE take saved with FUNC + YES lands in RECORDED the same way
4. PROJECT RAM > RENAME a sample with a long name: SAMP shows its first 7 letters
5. everything from v0.45

**known issues**
- the copy to RECORDED is unproven on hardware: please report anything odd (a recording missing from RECORDED, or the +Drive busy for long after a save)
- BOUNCE recording is still unproven on hardware (reports say it records nothing for some of you). next up: the test emulator runs the Digitone's two processors together, so the whole BOUNCE path from trig to playback gets tested
- a +Drive library from another build that this one doesn't recognise is left alone: recordings then stay in the project only
- the name's default stays RECnnn, not the DT2's REC0000
- everything listed for v0.45
