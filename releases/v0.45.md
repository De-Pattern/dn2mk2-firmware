# v0.45 · ROOMIER

patcher: de-pattern.github.io/dn2mk2/patcher.html

BOUNCE is back and fixed, plus a bigger +Drive library, SELECT UNUSED, recorder trigs on the [TRIG] LEDs, and the SAMP bug where scrolling past your samples kept playing the last one

**fixed: v0.44's freeze with BOUNCE**
- on v0.44, picking BOUNCE in MACHINE SEL froze the unit, and a project that held a BOUNCE track froze it at every power-on. the code that fetches each control's label read from an address where nothing lives. fixed, and BOUNCE is back in MACHINE SEL
- projects saved with BOUNCE tracks are safe to load again on v0.45
- if your unit is still stuck from v0.44: hold FUNC while powering on, then TRIG 2 (EMPTY RESET). your +Drive is safe. then update to v0.45
- the safety gates now power the unit on with every machine of ours on the tracks, and pick every machine through MACHINE SEL's real list. that's the check v0.44 was missing
- and every emulator check now fails if our code reads from an address where nothing lives, the kind of read behind v0.44's freeze

**the +Drive library holds 16,384 samples** (was 2,048; spacem0nkey hit the wall with 18 GB free)
- nothing to do: your library is read as it is, and the first sample past 2,048 makes the extra room by itself
- every sample and folder stays where it is. an older firmware still reads the first 2,048
- the import page reads the new size from the unit

**SELECT UNUSED** (PROJECT RAM, as on the DT2; Wolljamin)
1. FUNC + YES → PROJECT RAM → RIGHT → **SEL UNUSED** (last in the menu; DELETE stays where it was)
2. it ticks every loaded sample that no pattern in the project uses: no kit's SAMP and no SAMP p-lock in any of the 128 patterns
3. **UNLOAD n?** → YES empties those slots. they stay on the +Drive if they came from there
- if there's nothing to unload, nothing is ticked

**recorder trigs on the [TRIG] LEDs**
- while the BOUNCE REC panel is open: a recorder trig lights red, a one-shot yellow (dim yellow when spent), the playing step white, and the rest go dark so note trigs don't show through
- close the panel and the LEDs are exactly the normal ones again

**fixed**
- scrolling SAMP past the last loaded sample (or onto OFF) kept playing the last loaded sample on every trig. the OS glides every knob, SAMP included, and the "LFO steps through your samples" code mistook that glide for an LFO. SAMP and SLCE never glide now; an LFO on SAMP still steps through your samples

**removed**
- PING (the filter), to make room. sounds saved with PING load with Multi-Mode instead. RING becomes Multi-Mode's resonance, so check the level: they can be loud

**test**
1. MACHINE SEL → BOUNCE: the page draws, no freeze. save, power off and on: it boots
2. SAMP on a ONESHOT track with a few samples loaded: scroll past the last one and play trigs: silence, not the last sample. scroll back: each one plays
3. PROJECT RAM → SEL UNUSED: only samples no pattern uses are ticked; UNLOAD n? removes just those
4. BOUNCE REC panel open: place a few recorder trigs and a one-shot: red and yellow LEDs, the playing step white; close the panel: normal LEDs
5. send samples past 2,048 into the +Drive library (import page or dn2samples.py): they keep going; reboot: all there
6. everything from v0.44 (BOUNCE recording, recorder trigs, QREC/QPLAY)

**known issues**
- BOUNCE recording itself is still unproven on hardware: please report anything odd
- if you go back to an older firmware while the library holds more than 2,048 samples, those past 2,048 are hidden there. don't send new samples to the library on the older firmware, or it may reuse their space
- SELECT UNUSED doesn't see sounds from the preset pool locked on trigs (sound locks) or the clipboard: a sample used only there counts as unused
- the LED colours are as the palette defines them; how they look at each LED INTENSITY setting is unchecked on hardware
- preset pool trig locks don't work with the mod's machines yet
- the take's start against the step (BOUNCE) is unverified on hardware
